docker 网络

默认bridge ,桥接模式

容器内部有容器网络，容器可以根据分配的IP 地址进行通信
容器网络和宿主机网路隔离

可以指定容器加入不同子网，
在不同子网的容器之间不能直接通信，
在相同子网的容器之间可以相互通信,docker 子网内部有一个dns机制，可以把名字转成IP地址
因此，同一个子网的容器，可以直接使用容器名字互相访问，而不必使用IP地址

host 模式

docker 容器直接共享宿主机的网络
容器直接使用宿主机的IP地址，无-p 映射端口，容器服务直接运行在宿主机的端口上
通过宿主机的IP地址和端口，可以直接访问到容器的服务
mac 需要开启设置
开启路径是：Settings → Resources → Network → Enable host networking。

直接用宿主机的IP地址和端口，可以直接访问到容器的服务

none 模式

容器不联网

查看docker 网络

docker compose

容器编排技术
使用yml文件管理多个容器，里面列出了容器之间是如何创建以及如何协同工作的
docker compose 文件可以被理解成一个多个docker run 命令 按照特定格式列到了一个文件中

docker 为每一个 compose 文件会自动创建子网，同一个 compose 文件中定义的所有容器自动加入同一个子网，所以在文件中不用二外写入网络创建和指定子网

compose 文件 可以自定义容器启动顺序

动手操作 部署nextjs 项目到docker 容器

官方文档：https://docs.docker.com/guides/nextjs

下面进入主要部署阶段将项目打包，打包产物放到docker 里面的ngnix 容器中，然后通过端口转发进行访问
即打包静态产物上传服务器后，修改ngnix配置指向这个目录，即可访问到项目

准备工作

使用合适node 版本，防止镜像生成失败

方式一： Next.js with standalone output

这种方式将nextjs项目打包成node服务，适合全栈场景

Standalone output (output: “standalone”) makes Next.js build a self-contained output that includes only the files and dependencies needed to run the application. A single node server.js can serve the app, which is ideal for Docker and supports server-side rendering, API routes, and incremental static regeneration. For details, see the Next.js output configuration documentation (including the “standalone” option).

The container runs the Next.js server with Node.js on port 3000.

The .dockerignore file tells Docker which files and folders to exclude when building the image.

注意跟打包不同，打包的时候，output = export 的时候会将所有静态文件打包到out 目录下，
如果项目中有api 文件也会进行打包，所以当前项目将api 目录通过添加下划线前缀‘_’ 来排除, 避免打包
